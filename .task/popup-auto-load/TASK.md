# 扩展弹层与指定页面自动加载

状态：DONE

目标：将工具加载、布局显示、面板展开和元素选取分离，支持页面规则的默认布局显示设置，升级面板内开关，并清理被替代的实现。Chrome／Edge 和 Codex 继续共用一个核心。规范见 [CONVENTIONS.md](../../CONVENTIONS.md)，现有接入说明见 [Chromium 接入说明](../../adapters/chromium/README.md) 与 [核心说明](../../packages/core/README.md)。

### 已确认需求与实施取舍

| 控制 | 作用与边界 |
| --- | --- |
| 此页面自动加载 | 决定进入匹配页面时是否加载工具，不展开面板、不自动选取或抢焦点。 |
| 加载后默认显示布局 | 每条规则独立保存，只决定新实例首次自动加载时的布局初始值。本轮规划采用新规则及旧规则迁移值 false，减少初次加载对视觉检查的干扰；停用规则时保留这个偏好。 |
| 展开／收起面板 | 仅改变面板可见性，不开启或关闭布局显示。收起时结束选取及瞬时预览，布局开关值保持不变。 |
| 面板内“显示布局” | 实时控制本实例的页面边界与名称提示，初始取自动加载规则默认值；手动切换只影响当前实例，不回写规则。 |
| 选择页面元素 | 只能由用户明确开启；布局显示关闭时结束选取并停止拦截业务点击。 |
| 完全移除 | 释放全部实例资源，独立于收起面板；当前路径不会被后台立即重新加载。 |

“显示布局”关闭时不显示页面边界、高亮框或名称提示，组件树、尺寸与详情仍可在面板中使用。布局显示开启时沿用边界与悬浮名称，面板收起后允许被动悬浮查看名称，业务点击不被拦截。不会为每个元素同时堆叠常驻名称标签。

手动首次打开面板时以布局关闭、选取关闭初始化；已有实例则保持其当前布局状态。默认偏好仅初始化新实例，修改偏好、重复自动加载、同文档路径切换或 htmx 内容替换均不重置用户已经修改的现场状态。整页刷新／移除后重新创建实例时再按适用默认值初始化。

入口隐藏、专门截图模式等此前建议不作为已确认的本轮必做项；本轮先完成上述独立控制。

### 现有冲突与处理

| 现有行为／位置 | 冲突 | 处理 |
| --- | --- | --- |
| `auto-command.js` 调用 `core("open")` | 自动加载直接展开面板。 | 改为静默 `load`，只传规则的布局初始值。 |
| `view.open()` 同时装样式、收集节点、显示面板并 `setPicking(true)` | 面板、布局和点击拦截耦合。 | 状态分别管理；删除自动选取和自动加载时的焦点移动。 |
| `runtime.close()` 释放整个 active scope，`view.close()` 清理所有边界与节点 | 收起面板会关掉布局。 | 面板收起只释放面板所需资源；边界及业务观察按真实需求保留。 |
| 面板已有“显示边界”复选框 | 再增加开关会出现两个重叠控制。 | 复用并升级为顶部“显示布局”开关，统一一个状态源，替换 `.outlines` 的直接驱动逻辑。 |
| `renderOverlay()` 只根据 `opened` 判断可见 | 面板展开会带出高亮；面板收起无法独立预览。 | 页面标记统一受布局开关控制，面板可见性只影响面板自身。 |
| 扩展主按钮“打开／关闭检查器”分别 open／destroy | 收起、工具就绪、移除含义混合。 | 主按钮改为显示／收起面板；完全移除进入折叠的次级操作，保留明确清理入口。 |
| 自动加载取首条命中规则，弹层另算 exact／covering | 不同规则的默认值可能按存储顺序生效，显示与实际不一致。 | 引入单一规则解析器，由后台及弹层共用，明确优先级。 |
| 测试要求 `close.resources.active === null` | 在布局显示仍开启时已不符合新契约。 | 改为验证面板资源释放、布局继续存在；全部关闭与 destroy 仍严格校验归零。 |
| 核心／Codex 文档将 close 描述为释放全部活动检查 | 与新的独立控制冲突。 | 随实现更新唯一规范与接入文档；历史验证记录保留其原始含义。 |

### 核心状态与资源契约

- 单一权威状态包括 `panelOpen`、`layoutVisible`、`picking`，页面实例是否存在由 registry／absent 判断。view 负责渲染与业务节点数据，不再另存一套同义 `opened` 控制状态。
- 保留 `open`、`close`、`toggle`、`destroy`、`status` 命令名称，前三者仅作用于面板。新增 `load` 用于静默初始化，新增 `set-layout` 用于明确设置布局可见性。序列化入口增加 options 参数并严格校验。
- `load` 通过 `{layoutVisible: boolean}` 接收新实例初始值；`set-layout` 使用同一字段显式更新已加载实例，未加载时明确报错，不隐式打开面板。旧的一参数 `open()` 仍可调用，首次创建按已声明的布局关闭初始值处理；非法选项在改变实例前拒绝。
- `status` 返回上述独立状态。保留 `state: open/closed/absent` 作为面板可见性的派生字段，避免不必要地破坏既有调用；不能再据它推断布局显示。重复 `load/open` 不重新应用默认值，也不创建第二个实例。
- 资源按 lifetime、业务检查、布局覆盖层、面板区分所有权，不让一个 panel open scope 承担全部资源。业务收集与观察仅在面板或布局需要时运行，两者都关闭后释放业务 DOM 引用、观察器及待执行任务；保留最小启动入口与导航／宿主移除清理。
- 边界样式、元素属性、名称浮层及被动指针监听归布局资源；关闭布局立即撤销，面板收起不撤销仍开启的布局资源。选取拦截仅在明确选取期间有效；关闭布局或收起面板均结束选取。
- 宿主移除、导航、初始化失败和 destroy 全部沿用完整清理及错误回滚要求。跨执行世界保护保留，不接管或覆盖其他实例。
- `Alt+Shift+L` 与页面启动入口只切换面板，不隐式打开布局或选取。

### 规则、迁移与默认值冲突

- 升级设置到 version 2，规则新增必填布尔字段 `defaultLayoutVisible`。合法 v1 数据只通过一个迁移入口补 false，保留 id、pattern、enabled 并一次性持久化；v2 不允许缺字段兜底，损坏或未知版本明确报错且不覆盖原数据。
- 后台统一串行读写／迁移；自动加载与弹层通过同一规则模型工作，避免各自添加旧字段兼容分支。v1 适配仅承担存量迁移，移除条件是明确停止支持 v1 存量设置；正常业务路径只使用 v2。
- 生效规则优先级：已启用且匹配的精确页面优先；通配规则按路径非通配字符更多、通配符更少优先；再按规范化 pattern 的固定字典序决定，结果不依赖添加顺序。
- 停用的规则不作为“禁止本页”的排除规则；停用后仍有通配规则命中时，工具可能继续自动加载，UI 必须展示有效状态。沿用不从当前页快捷开关暗改通配规则的保护，展示作用来源并引导管理明确范围。
- “默认显示布局”只编辑明确归属的规则。通配规则覆盖多页时，修改需在该规则管理中明确展示影响范围；需要当前页不同默认值时通过精确规则覆盖，不能无提示更改整站偏好。
- 快捷开关无法只影响当前页时，展示生效规则来源，并提供管理命中规则／创建精确覆盖的操作入口，不能只留下没有处理入口的灰色控件。启用设置所需的主机权限仍由明确用户操作触发。
- 保留当前文档／路径去重与用户手动移除保护。保存默认偏好不使用 force 重开已有实例；新增／启用规则可在当前页缺少实例时静默加载，现有实例不被自动配置覆盖。
- 自动加载关闭或未授权时，默认显示偏好保留但不执行。权限仍按主机明确申请；现有更新配置入口保留，它解决的是浏览器旧 manifest，并非无效代码。

### 验收矩阵

| 场景 | 必须满足 |
| --- | --- |
| 自动加载，默认布局关闭 | 面板收起、无边界／名称／高亮、不选取、不抢焦点、业务点击正常。 |
| 自动加载，默认布局开启 | 面板收起、边界及被动悬浮名称可用、不拦截点击。 |
| 面板开／关 × 布局开／关 | 四种组合均可达；切面板不改布局值，切布局不改变面板可见性。 |
| 面板内关闭布局 | 边界、名称和页面高亮立即消失，选取结束；组件树和详情可用。 |
| 收起面板且布局仍开 | 边界继续显示，业务节点变化继续正确刷新；无选取拦截和面板任务残留。 |
| 手动修改布局后重复加载／修改默认值／SPA 切换 | 不重置现场状态、不重新弹面板；新实例或整页刷新按规则默认值初始化。 |
| 同时命中精确规则和多个通配规则 | 默认值选择确定且 UI／后台一致；作用范围可见，不假显示关闭。 |
| v1 迁移、缺字段、未知版本、并发保存、权限撤销 | 数据不丢失，v2 严格校验，失败不覆盖原配置，也不改页面运行状态。 |
| 重复启停、DOM 替换、宿主移除、导航及异常回滚 | 资源随需求启停；两者关闭时无业务观察／引用，destroy 后全部归零。 |
| 两端与构建 | Chrome／Edge 和 Codex 共用核心一致；严格 CSP／Trusted Types、拖拽、树层级与移动视口回归通过。 |
